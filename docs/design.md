# デザインの基準

更新: 2026-09-07

目指すのは、金属の作業台の上で記録を整理するような、明るく静かな作業空間。主役は装飾やダッシュボードの数値ではなく、映像、その瞬間の判断、作業者の言葉である。

## 色と文字

| 用途     | 色        | 役割                                                         |
| -------- | --------- | ------------------------------------------------------------ |
| 作業面   | `#f5f7f6` | 冷たさのある明るい背景。長い文章や映像の周囲に余白を置く。   |
| 主操作   | `#174c43` | 深い工房の緑。記録開始、次へ、公開などの主要操作。           |
| 確認待ち | `#e1a842` | 判断点、未回答、注意を示すアンバー。本文色として多用しない。 |
| 文字     | `#25342f` | グラファイト。和文本文と見出しを読みやすく保つ。             |

英字ブランドには太めのhumanist sansを一系統だけ使う。和文はNoto Sans JPを中心に、利用可能な日本語サンセリフへフォールバックする。数値や時刻は桁が揃う表示とし、装飾的な書体を追加しない。本文と補助ラベルの大きさを区別し、日本語の行間を十分に取る。スマートフォンの文字拡大は実機で確認する。

状態を色だけで伝えない。「下書き」「確認済み」「未回答」「サンプル」を言葉と形で区別する。コントラストは実際の前景・背景の組み合わせで確認する。

## 画面の骨格

スマートフォンの下部タブはホーム、記録、Wiki、質問。チームと設定は補助導線に置き、作業中の主操作を増やさない。デスクトップでは同じ情報構造をサイドバーに広げ、右側へ記録の続きと未記録の質問を置く。

ホームには一つの明確な記録開始操作と、再開すべき作業を置く。全てをカードに囲まず、見出し、罫線、余白、行のまとまりで優先順位を作る。主要情報がない場合は、空の実績カードを並べず最初の一歩を示す。

## 中心となる表現

- **記録:** 動画を大きく、工程名の入力を短く。撮影中は経過時間と終了操作を明確にする。
- **解析:** 映像と時間軸を対応させる。観察できたことと、質問が必要な判断を別に示す。抽出フレームを連続映像の完全解析のように演出しない。
- **聞き取り:** 一度に一問。対応時刻、質問、質問理由、入力欄の順で読めるようにする。回答の中断・再開を自然な操作にする。
- **Wiki:** 手順・判断・注意を読み分け、出典と確認状態を本文の近くへ置く。根拠は小さな脚注だけに押し込めない。
- **質問:** 結論、条件、出典の順。根拠不足の場合は何が未記録かを示し、質問を残す導線へつなぐ。

技術ページを紙のマニュアル風に固定するより、知識と元の映像を行き来できる構造を優先する。出典を開くと、押した判断の時刻または回答原文が直ちに分かる。

## 操作と状態

主要タップ領域は44px以上。固定操作は端末のセーフエリアを含めて配置し、ソフトウェアキーボード表示時も入力と送信を続けられるようにする。フォーカスを視認でき、キーボード操作で主要機能へ到達できる。

画面移動やパネル表示は短い控えめな動きにとどめる。`prefers-reduced-motion`を尊重する。常時動くAI装飾や、実際の進行と無関係な完了率は使わない。

各入力・非同期処理には、処理中、成功、失敗、再試行を用意する。保存前の内容を守り、失敗理由と次にできる操作を示す。「AI」「作業者主導」「サンプル」の処理区分を体験中に見失わせない。

## 視覚確認

390px前後の縦画面とデスクトップで、ホーム→記録→聞き取り→Wiki→質問を確認する。長い日本語タイトル、空のチーム、回答途中、出典が動画ではない場合、ネットワーク不通を含める。はみ出し、タブと本文の重なり、色だけの状態表示、ボタンの押しにくさを修正してから完成とする。

この文書はデザイン意図を示す。採用したフォント・素材の正確なファイルとライセンスは配布物の通知文で管理する。
