# ラップトップのCodexと製作動画の実行接続

元スキル: codex/project-process-video-skill @ bcc7c307bf343a73d7e9478489c5552b50a003f9。
作業: codex/process-video-ai-runtime → main。Issue #25 / PR #26。元スキルと#24のWiki参照変更を含む。

2026-09-13のユーザー指定により、接続先を大会に持ち込むラップトップへ変更。アプリの固定AI処理を、このPCでChatGPTログイン済みのCodex CLIへ渡す。通常のChatGPT画面を操作する方式ではなく、CodexのChatGPT認証を使用する。

## 起動

1. このPCのCodexを通常のChatGPTログインで利用できる状態にする。Node.js 22.13以上と依存パッケージが必要。
2. .env.local にアプリの VITE_SUPABASE_URL / VITE_SUPABASE_PUBLISHABLE_KEY と、利用工房の BATON_ALLOWED_TEAM_ID を設定する。secret/service_roleキーやアプリJWTを書かない。
3. テスト用記録を作る場合は VITE_BATON_VERIFICATION=true を設定してから npm run build。このビルドでは記録のWiki自動反映を停止する。通常運用へ戻す前に検証記録を除き、この値をfalseにして再ビルドする。
4. Windowsで npm run start:laptop。起動時にChatGPTログインを確認する。実行ファイルは Get-Command codex で解決し、バージョン固定パスを保存しない。
5. https://meisters-baton.vercel.app/#settings をこのPCで開き、Meister’s Batonへ通常ログイン。「AIサーバーの接続先を設定する」→「このPCのCodexに接続」。接続成功後、AI送信を有効にする。「Wiki閲覧権限を確認」は記録を追加せず本文・添付の取得を検証できる。ローカル配信 http://127.0.0.1:8787/#settings でも同じ操作を使える。
6. 作業記録の「作業の3D解説動画を作る」でWiki接続確認→Codex生成→構成確認→MP4書き出し。MP4は端末内に保存され、ダウンロードできる。

起動中のPCとインターネット接続が必要。待受けは127.0.0.1:8787のみ。外部公開・Tailscale・他PCからの接続は追加していない。サイトからの接続でブラウザーがローカルネットワークへの許可を求めた場合は許可する。ブラウザーや組織設定で拒否される場合はローカル配信を使用する。ブラウザーのセキュリティ設定を無効にする手順は使用しない。

本番ビルドはGitのmainからVercelで作成する。検証端末の.env.localやVITE_BATON_VERIFICATION=trueを本番へ持ち込まない。サイトの接続ボタンは認証情報なしで固定接続口のprovider/scopeを確認してから接続先を保存する。Wiki・生成リクエストでは本人JWTと工房を引き続き検証する。

## 認証・実行境界

- server/laptopGateway.ts: 固定の解析・記事生成・記事検索・製作動画APIのみ。指定工房とSupabase本人JWTを検証。未知のHost/Originは拒否し、一般的なプロキシや任意コマンドAPIは提供しない。
- server/codexProvider.ts: codex exec --ignore-user-config --ephemeral --sandbox read-only、ChatGPT認証固定。シェル・Web検索・外部アプリ・ブラウザー・画像生成・サブエージェント等を無効化。選択資料をstdin、画像を一時ファイルで渡す。JWTはプロンプト・引数・子プロセス環境へ渡さない。
- 出力JSON、出典ID、部材ID、場面連続性を検証。ツールイベントが返った場合は成功扱いしない。1件ずつ実行し、利用者ごとの時間帯上限も設ける。通常AIと動画APIの上限カウンターは別で各12回/時。再起動でリセットされる端末用の制限。
- Codex生成は最大5分、アプリ待受けは6分。Windowsでは対象子プロセスの終了を待ってから一時領域を片付ける。
- server/wikiContext.ts: 既存CLIと共通の資料取得。Authサーバー検証→工房所属→RLSの順に、本人が閲覧できる取込Wiki・編集・作業記事を読む。元MeisterWikiへはアクセスしない。
- MP4は別IndexedDBへ工房/記録ID付きで保存。画面・アカウント切替後に古い結果を表示しない。記録削除・端末全消去時は生成動画も削除。サインアウト自体では記録を消さず、別工房の画面には表示しない。

## 検証と制約

ラップトップのChatGPTログインで実Codexから構造化JSON応答を取得。本番アプリアカウントの通常ログインでWiki本文85件・編集3件・作業記事0件を取得し、選択添付1件のSHA256とバイト数の一致を画面で確認。SQLでの認証模擬を本番JWT試験と扱っていない。

型検査、126単体/API試験、ビルド、既存記録フロー7件と1080p MP4試験を通した。最初のブラウザー試験はサンドボックスの実行権限で起動できず、通常ユーザー実行で成功。共有依存のフォント配信も修正してMP4試験を再実行した。最終確認の基点は上記SHAと一致し、検証ビルドでWiki自動反映を停止したまま実行している。

同じ本番ログインで取込Wikiを読み、実Codexから「26代の外皮積層：材料と工程の関係」という5場面の構成を生成。アプリ画面から1920×1080・46.997167秒の実MP4を描画してIndexedDBへ保存し、最後まで再生して ended=true / error=null を確認した。再読み込み後も同じ尺・解像度で復元できた。Codex内ブラウザーのダウンロードイベントは取得できず、ダウンロード先ファイルの保存は未確認。これは本文を根拠にした接続検証用の概念図で、当日の作業実績ではない。初回は150秒の上限とWindowsの一時フォルダー終了競合で失敗し、上限と終了処理の修正後に成功した。

検証メモが既存のWiki自動反映により外皮ページへ追記されたため、今回の追記だけを復元。直前の本文・events・mediaと完全一致を確認し、変更履歴は保持。以降は検証ビルドで自動反映を停止。

描画は位置・回転を補間する共通3Dモデルの概念図で、無音H.264 MP4を生成する。製法の承認済み教材ではない。任意形状の変形・切断・手の接触・全工程再現、HTML/CSSを正本にした映像制作、独立した再描画パッケージ、全フレーム検査、初学者の理解レビューなど、元スキルの全要件を満たした状態ではない。添付取得のハッシュ検証と、AIが添付全体を視覚的に確認したことも区別する。

公式の実行方式: https://learn.chatgpt.com/docs/non-interactive-mode 。モデルの利用可否・利用枠はログインしたChatGPTアカウントに従う。
