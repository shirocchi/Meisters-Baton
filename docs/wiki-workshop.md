# 記録が育てる技術Wiki

技術Wikiは、工程から探す入口、写真・動画、本文、編集、更新履歴を備えます。元の移植アーカイブは保持し、工房ごとの編集を重ねて表示します。モニターの縮小設定はページやタブを移動しても保持されます。

## 記録から本文への自動反映

ログインした工房にWiki閲覧権限がある場合、撮影・動画取込・作業メモの保存後に処理します。作業名、メモ、既存の映像解析、回答にある関連語を、実際のWikiページ名・階層・見出し・本文へ照合します。工程名への一致を優先し、同点や関連の弱い記録はトップの「工程の確認が必要な記録」に残します。反映先を選べば手動で取り込めます。デモとDiscordからの初期アーカイブは対象外です。

対応する節へ、メモ・観察・回答を出典付きで自動反映します。同じ記録の解析や回答が更新された場合は、その記録の範囲を差し替えます。すでに書かれた他の記録と元の手順は維持し、手法の異なる記録を共通の施工条件として断定しません。数値の矛盾を自動で判定・解消する機能ではありません。

反映処理そのものは外部LLMを使わない関連語照合です。動画だけから新しい観察を生成したとは表示しません。既存の映像解析を行った場合はその結果も対象となり、動画だけの記録は映像と切り出し画像への入口として反映します。新しい外部AI送信やAPIキー設定は追加していません。

更新はアプリを開いている間に行い、通信が戻れば再開します。アプリを閉じた後のバックグラウンド処理ではありません。記録は先に端末へ保存されるため、Wiki側の通信失敗で撮影記録は失われません。

## 映像と画像

- 移植した画像は認証付きで取得し、画面に近づいた画像から読み込みます。拡大と保存ができます。
- 作業記録のカードから、元動画・場面の開始時刻・切り出し画像・メモ・職人の回答をまとめて確認できます。
- Wiki編集画面から画像・動画を追加できます。既存のprivate `team-media` を使います。
- 自動反映時、50MB以下の元動画は同じ工房へ一度共有します。超える動画は元の端末に残り、本文側にもその制約を表示します。
- 共有する記録のスナップショットには、元動画への参照と最大6枚の既存フレームを含めます。共有Wiki本文を端末のLocal StorageやService Workerへ保存しません。

## 手動編集と復元

「編集」ではページ全体または節を選べます。見出し・太字・箇条書き・リンクのボタン、仕上がり表示、画像・動画追加に対応します。保存していない内容がある場合は破棄を確認します。保存やファイル配置中は入力を固定し、古い入力状態での上書きを防ぎます。

保存は、編集を開いた時点の版番号を条件にした比較更新です。別の端末や自動反映が先に更新した場合、入力を保持したまま最新本文との比較を促します。更新のたびに直前の版を保存します。履歴からの復元も新しい版になるので、取り消した更新も失われません。画面では直近50版を取得しますが、古い履歴を削除しません。

復元しても記録の取込済み識別情報を保持し、同じ記録を再読込だけで勝手に再反映しません。その後に元の記録へ新しい情報が追加された場合は、新しい更新として反映します。

## データと検証

`wiki_page_edits` は工房ごとの現在の編集、`wiki_page_revisions` は過去版です。両方にRLSを設定し、許可された工房のメンバーだけが読めます。クライアントの直接INSERT・UPDATE・DELETEは許可しません。`save_wiki_page` が本人・工房・閲覧許可・対象ページを確認し、ロック、版番号比較、過去版保存、更新を一つのトランザクションで実施します。特権処理は非公開スキーマに置きます。

`supabase/tests/wiki_workshop.sql` は、許可メンバーの保存、原文保全、競合拒否、復元、直接書換え拒否、非所属・匿名の拒否を検査します。実行全体をBEGIN／ROLLBACKで囲み、実データに試験結果を残さないでください。

ブラウザー試験では、縮小状態の維持、本文編集、競合時の入力保全、復元後の再反映防止、動画の実バイト取込からWiki内再生、画像追加、スマホ表示を確認します。
