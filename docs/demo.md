# 3分デモと当日の分担

更新: 2026-09-07

伝えることは一つ。「先輩の手元だけでなく、判断した理由まで次の世代へ残す」。記録者と後輩が同じ記録を使う一周を見せる。

## 事前準備

- 利用・展示してよい作業動画を選ぶ。第三者の顔、音声、機密が含まれる場合は扱える範囲を確定する。
- 作業者に、映像では分からない判断を3件挙げてもらう。例: 止め時、材料の状態、失敗の兆候。サンプルの答えを実際の工程の正解として使わない。
- 実データ用のチームと、明示されたサンプル体験を分ける。サンプルへ切り替えた場合はそう説明する。
- 実動画の解析は発表前に済ませ、ライブでは質問・回答・知識化・根拠・検索を実演する。事前解析済みであることを表示する。
- 一つの回答欄をライブ入力のために空ける。固有の短い判断条件をその場で追加し、生成結果へ反映されることを見せる。
- 実機の画面収録、音声、通信、画面ロック設定を確認する。バックアップの画面収録はライブ映像と区別する。

## 台本

| 時間      | 操作                                         | 話す内容                                                                                           |
| --------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 0:00–0:20 | 実物または展示許可のある製作写真を示す       | 「この仕上がりを生んだ判断を、次の代に残したい。動画や日記だけでは、細かな判断が抜け落ちます。」   |
| 0:20–0:40 | 記録を開き、判断が必要な場面を再生           | 「ここで手が止まっています。映像には動作が残っても、止めた理由は残りません。」                     |
| 0:40–1:15 | 対応する質問を開き、一つの回答を入力         | 「Batonは、分からない部分を作業者へ聞きます。」映像だけにない判断条件を短く答える。                |
| 1:15–1:45 | 技術ページを生成し、回答の出典を開く         | 「いま答えた条件が知識になりました。説明した人の原文と、映像へ戻れます。」内容を確認して公開する。 |
| 1:45–2:15 | 後輩として自然文で質問                       | 「初めて担当する後輩は、現場の迷いから尋ねられます。」追加した知識を示し、出典へ戻る。             |
| 2:15–2:35 | 一覧へ戻り、保存された記録と未記録質問を示す | 「答えがない疑問は、次に残すべき技術になります。工程が変わってもこの流れを使えます。」             |
| 2:35–2:50 | 実際の改善前後を1件示す                      | Codexで発見した問題、修正、検証結果を短く示す。当日分と事前分を区別する。                          |
| 2:50–3:00 | 記録と回答が並ぶ画面で終える                 | 「先輩の判断を、次の作り手が必要な瞬間へ。まずは自分たちの製作現場で使います。」                   |

発表時間の正式な案内が短い場合は、一覧紹介と改善例を圧縮する。根拠へ戻る場面を削らない。重量などの数値を話す場合は、本人が確認した値と比較条件を使う。

## 障害時の進め方

端末内の保存済み記録と原文を最初の代替手段にする。AI接続がなければ、作業者主導の聞き取りと回答原文から作る体験へ進み、ライブAIではないことを説明する。サンプルへ移る場合はサンプル表示を維持する。途中で答えが変わらない固定画面を、入力から生成した結果として見せない。

## 3人の責任

| 担当                    | 実装・検証の責任                                                            | 発表時                        |
| ----------------------- | --------------------------------------------------------------------------- | ----------------------------- |
| Product / Domain        | 動画と判断の正解、質問の質、生成主張の確認、後輩テスト、事前開発の開示      | 課題と判断の意味を話す        |
| Experience              | 記録→対話→Wiki→検索の接続、スマートフォン操作、空・失敗・復帰状態、画面収録 | 端末を操作する                |
| Intelligence / Evidence | AI入出力、出典の検証、認証・同期・映像アクセス、通信障害の復旧              | 接続状態と根拠のQ&Aを担当する |

各担当が自分のCodex作業を持ち、共通の型と受け入れ条件で統合する。変更の担当範囲はGitで見える状態にし、共有ファイルを同時に書き換える前に調整する。

当日は最初に、事前基盤から何を実質的に作るかを合意する。実動画で発見した欠落、質問改善、後輩の迷い、実機上の問題から開発課題を選び、途中で一度統合する。提出前には主要フロー、再起動復元、未知質問への応答、出典リンクを全員で通す。

## 証明として残すもの

実行したテスト、修正前後の画面、質問の改訂理由、利用者の観察結果、事前基盤からの差分を記録する。コミット数を改善回数と同一視しない。実施していない利用テストや性能値をピッチに入れない。

審査と事前開発条件の正本は [pre-event-disclosure.md](pre-event-disclosure.md) の参照先を確認する。
