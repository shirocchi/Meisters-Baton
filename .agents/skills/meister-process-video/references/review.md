# レビューと修正の往復

制作側の報告を読んだ後に、現在のMP4と実際の画像、必要な元記録を確認する。ハッシュや形式検査の合格から内容の正しさを推定しない。

## レビューの中心

- 全体のどの部分か、何と何を扱っているか。
- 対象の形、表裏、道具と手の接触、操作する方向を追えるか。
- 処理前後と、最終的に処理する範囲が分かるか。
- 前の場面から同じ部品・状態が継続するか。
- 苦労や注意が、どの操作に関係するか。
- 図が、根拠のない材質・寸法・力・原因・対策を断定していないか。
- デザインとして、最初に見る対象が明確か。構図・余白・文字組み・配色・照明が揃い、重要な接点と変化を読み取りやすいか。

デモでは残る指摘を絞る。「不明なことが残る」だけで全面的な作り直しにしない。形と操作を誤解させる指摘と、写実性の向上だけの指摘を分ける。手が不気味でも、支持点が役立つならその情報を残して造形を簡略化する。

## 理解と画面デザインの確認

制作台帳で得た知識で、映像中の説明不足を補っていないか確認する。視聴後に分かることと、それを伝える画面内の形・接触・変化・短い字幕を対応付ける。「字幕に工程名がある」「工具が動く」「出典がある」だけでは操作内容の説明を満たしたとはしない。

製作内容の指摘とデザインの指摘をそれぞれ残す。画面が整っていても根拠・形・接触・状態の誤りを見送らず、根拠が揃っていても視線が散る配置・接点の小ささ・読みにくい文字組みを見送らない。修正は [画面デザインの基準](production.md) と照合し、共通スタイルやモデルの変更が他場面へ与える影響も確認する。

人による理解確認を行う場合は、先に正解を説明せず、何をしていたかと記録にある苦労を本人の言葉で説明してもらう。AIによる自己確認と区別して記録する。静止画のみを見た場合は、テンポや字幕の読了時間を合格にしない。

## 訂正記録

| 欄 | 内容 |
|---|---|
| 対象 | 場面ID・モデルID・操作ID、実MP4の時刻 |
| 種類 | 事実訂正／見せ方／将来の改善案 |
| 現在の問題 | 視聴者が何を誤解するか |
| 根拠 | 元動画PTS、Wiki本文・画像、日誌、ユーザー／有識者の回答 |
| 修正 | 形・接触・状態・字幕のうち何を変えるか |
| 再確認 | 変更場面と共有モデルが使われる他場面 |

製作の訂正は根拠→共通モデル／操作→各場面→字幕へ反映する。既存の承認がある知識を変えた場合、変更部分は未承認に戻す。レビュー意見、ユーザー補足、製法の有識者承認を同一視しない。

## 検証の伝え方

次の確認を別々に記録する。

- メタデータと全フレーム復号を実行した。
- 何場面の、どの時刻の抽出画像を実際に見た。
- 動画を連続再生して視聴した／していない。
- 製法を有識者が確認した／未確認。
- 初学者が理解できるか実際に確認した／未確認。

フレーム画像差分や層の座標検査は補助である。画像差分ゼロは意図した読了時間かもしれず、座標が接触していても持ち方の意味までは確認できない。

## 他の制作タスクへ渡すとき

現在の制作仕様、元素材、出典画像、今回の訂正、編集可能なソース、出力先、どこまで進めるかを渡す。会話全文や一回の完成MP4だけに依存しない。

ユーザーが「試作を見てから」と指定した場合は、全工程低負荷版→レビュー→訂正→高解像度版の二段階にする。すでに最終動画まで依頼されている場合は、内部で低負荷版を自己確認してから進め、毎場面の承認を新設しない。
