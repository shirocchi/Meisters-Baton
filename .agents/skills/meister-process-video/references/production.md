# 映像・描画・検証

## 絵コンテから描画へ

各場面に操作前、接触、動き・変形、操作後を定義する。前の場面の部品状態を次へ受け渡す。未知の途中操作を省く場合、袋が急に消える、切った物が元へ戻るなどの構造的な矛盾を残さず、短い編集カットで分かるようにする。

本物の外観の完全再現より、製作を理解するための特徴を優先する。完成物の輪郭、どこが今回の部品か、型の内外、面の向き、接触が重要。プロペラなら単に半円断面の長材を2本並べるだけでは全体を認識しづらい。中心の接続部、一枚ごとの輪郭、立体の向きが分かる概形から対象へ寄る。正確なCADがなくても全体の関係は示せるが、特定年代の実物再現とは区別する。

全体から部位へ寄るときは、同じ輪郭・特徴点・面を追えるようにつなぐ。作業モデルを元資料と同じ視点で見比べ、接触する縁・側面・くぼみなどを単純化で失っていないか確認する。寸法や見えない断面が不明でも、観察できる作業上の特徴は残す。

断面を見る時は、切断平面や透過範囲を提示してから同じ形状へ寄る。完成ブレードの分解図を、外皮積層・フランジ・ウェブ等の個別工程の代わりに流用しない。

位置が特定できない不具合を示す場合は、実物上の断面位置へ結び付けず、独立した概念図に切り替える。例えば「浮いた」という記録だけで、特定の箇所の浮きと、その場で押さえて解消した動作を結び付けない。分かっている作業動作と、記録にある苦労の説明を接続するときも、未確認の原因・対処を作らない。

実物上の向き・場所が未確定でも、根拠のある部位名や一般的な形の説明まで省かない。必要なら一般形の3Dで部位を示し、当日の実物座標や不具合位置へは結び付けない。例えば前縁・後縁の一般的な位置を説明することと、元カメラの左右へ割り当てることを分ける。

## 手・工具・材料

- 支える、つまむ、押さえる、広げるの区別が付く簡略な手を使う。手袋風の色と輪郭、親指、掌の向き、短い手首で接触主体を整理できる。細かい肌・爪や、人間らしさを狙った不十分な指造形は優先しない。
- 保持点と材料の動きを合わせる。物が離れた所から動く、手が物を貫通する、押している手と離れている指が混在する場面は修正する。
- 「局所の実演」と「対象範囲へ操作を終えた状態」を分けて設計する。塗る・広げる・磨く等は対象面と到達範囲、切る操作は残す部分と取り除く部分、包む操作は中身と袋の内外を終端でも見せる。
- 材料の変化を供給点・接触域に対応させ、操作後の状態を根拠に沿って次へ受け渡す。工具が一部を動くだけなのに全域の色や形が自動で変わる描写を、処理範囲の説明に使わない。濡れの暗色化を脱泡成功と同一視しない。広範囲の反復を省略するときは、根拠のある別の接点や短い編集カットでつなぐ。重ねる操作では、新しい材料の搬入中にも既存の材料を残す。実層数が不明なら既存層は集約して示し、表示面数を実層数と誤認させない。
- 布、膜、硬い型、コアを同じ変形で扱わない。全体の精密物理より、接触点の近くで変形し、後の状態へ自然につながることを優先する。
- 手や工具の細かな軌跡・圧力が不明なときは代表操作として描く。持ち方を再現できる動画に見える場合ほど、観察済みの範囲と補間の境界を台帳に残す。

## HTML/CSSと3Dの画面デザイン

HTML/CSSは字幕・名称・レイアウトを、3D側は共通モデル・接触・変形・照明・カメラを担う。配色・文字サイズ・余白は共通のスタイル定義にまとめ、場面ごとに同じ値を別々に直す構成を避ける。3Dと字幕・強調表示を同じ秒単位の時刻から決定し、シークやフレーム抽出でも表示が一致するようにする。Manim等で描画済みの3D映像を使う場合も、その映像時刻とHTML/CSSの表示時刻を対応させる。

- **情報の優先順位**：動作する対象と、その瞬間に伝える主文を中心にする。同じ説明を上見出し・右欄・下字幕へ重ねず、用語の説明は必要な場面で表示する。右側の説明欄を全場面に固定する必要はない。
- **構図と余白**：全景で部位の関係を示し、操作場面では接点を十分大きく見せる。拡大前後で同じ面・向きを追えるようにし、余白を埋めるための装飾や、拡大による重要箇所の切れを避ける。
- **文字組み**：見出し・主字幕・補足の階層を決め、それぞれの文字サイズ・太さを全編で揃え、意味のまとまりで改行する。狭い欄に長文を押し込まず、語尾だけの改行や小さすぎる補足を整理する。原動画PTS・取得経路・補間の詳細は台帳へ置き、実層数との違いや概念図の注記など、その場の誤解を防ぐ情報を残す。
- **配色と照明**：手・工具・対象面の輪郭と接点を見分けられる明暗差を作る。影の濃さや手の造形が接触を隠す場合は整え、全編の色と光の方向を統一する。色や光沢の変更を、根拠のない材質・硬化・処理完了の表示にしない。
- **工程の表示**：視聴者の現在位置は「シートを重ねる」等の短い工程名で示す。管理用の場面IDだけで工程を説明しない。工程名・ラベル・字幕の表示を動作と合わせ、本文や接点を覆わない。

画面案は代表場面で構図・文字組みを確認してから共通スタイルへ反映し、全工程の低負荷版で一貫性を確認する。デザインの改善と製作内容の訂正を並行して進める。静止した図の拡大・移動だけで手や工具の接触・材料の変化を代用しない。生成図版を使う場合も、製作の根拠・編集可能な3Dモデル・動作データの代わりにはしない。

## 低負荷版と完成版

低負荷版も全工程を通す。解像度・影・細分割数を抑えることと、工程や接触を省くことを混同しない。初回の自己確認では、全体が認識できるか、物が何をされて変わるかを先に見る。

デモの残作業は次のように分ける。

| 優先 | 例 |
|---|---|
| 内容を誤解させるため直す | 完成物に見えない冒頭、誤った接触面、全面処理なのに縁を残す、袋や層の取り違え |
| 小さく改善する | 手の形・色、部品ラベルの位置、主要接点の拡大、重複字幕 |
| 後回しにできる | 正確な材質テクスチャ、全指の関節、実測されていない流体・布物性、撮影していない細部 |

高画質化は元の3Dシーンを目的の解像度で描き直す。低解像度MP4の拡大を高解像度レンダーと呼ばない。解像度だけを変えても、シルエット・手の形・処理範囲・接触の誤りは変わらない。

フレーム数は尺とfpsから算出し、秒ベースの動作時間を保つ。解像度を変える時は字幕座標・字号・行幅・画面余白・QA抽出点も整合させる。ライブラリの既定値や、以前の動画に固定された1280×720・24fps・206秒を引き継いだままにしない。最終版の少数フレームを先に確認してから全編を描く。

## 実行環境と再利用

提供済みの制作ソース・依存定義・動くPython環境等を調べる。新しいレンダラーを毎回ゼロから作る必要はない。既存の共通形状・操作データ・字幕・カメラ・エンコードを分けて再利用する。一方、特定の外皮の曲率や手の配置を他工程のモデルへそのまま移植しない。

依存が見つからない場合は、選んだPython等の環境にないことと、端末全体で利用できないことを分ける。既存の制作環境を確かめ、利用できる環境で同梱スクリプトを実行するか、既に許された代替手段を使う。

Manimで必要な曲面・透過・変形の反復が難しい場合は、既存のGPU描画や別の3D手段を選べる。道具の変更だけで製法の理解が改善したとはしない。新しい依存が必要なら目的を限定して導入し、実際に動いた環境・再描画コマンドを出力先へ残す。

人物や物の見た目を生成モデルへ任せる場合も、同一部品・接触・状態変化の整合を実物で照合する。生成画像や動画を製法の証拠にしない。

## 最終の確認

1. 実MP4の形式・トラック・尺・復号を確認する。各場面の始終時刻、音声なしの要件、fps、指定解像度と照合する。
2. 全場面の開始・操作途中・終了を抽出して実際に見る。終端だけでは握り方、貫通、めくり途中の破綻を検出できない。
   場面の中間時刻が操作途中とは限らない。材料の受渡し、手が離れる瞬間、反復の切替、処理範囲が広がる途中を選んで補う。抽出数を増やすこと自体を目標にしない。
3. 特に変更した共通モデルが使われる全場面と、場面間の接続を確認する。全面処理等は終端でも範囲を見せる。
4. 可能なら全編を連続再生してテンポ・読了時間・動きの理解を確認する。利用環境の閲覧制限がある場合は範囲を記録し、復号や静止画確認を連続視聴と呼ばない。
5. 受け渡しには成果MP4、編集可能なソース、出典・未確認事項、場面時刻、再描画と検証方法を残す。細かな台帳は一つの資料へ統合可。
