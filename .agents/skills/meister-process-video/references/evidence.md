# 根拠の確認と最小台帳

## 取得

Wikiの探索と取得は [Wikiの参照方法](wiki-access.md) に従う。アプリ内Wikiと取り込み済みMeister Wikiを参照し、取込原文・アプリの編集版・作業記録の根拠を区別する。出典付きのオフライン資料も使えるが、元サイトへのブラウザーアクセスを不足時の自動代替にしない。リンクがあることと読めたことを分ける。画像を使うときはアプリ内ページID、元ページ・添付ID、編集版、周辺の説明、対象年代、取得日、実際に見たこと、当該作業への適用範囲を残す。ハッシュ検証成功と画像の実見も別に記録する。

本文と画像が別年代・別製法なら混ぜない。古い画像は型と成形物の凹凸関係を説明できても、現在のコア材質・厚さ・具体的な工具を確定するとは限らない。静止画だけで見えない裏側や全操作順を作らない。

根拠が不足する場合は「何がないか」だけでなく「今ある根拠で何を描けるか」を判断する。代替形状を使うときも、完成物や対象部位が分かる特徴は残し、実寸CADや当日の細部の再現と誤認させない。

## 二段階の動画確認

最初は全体の工程候補・配置変更・字幕変化を拾う。次に、短い工程、持込前後、膜の除去、工具の接触、完成状態との不整合を優先して細かく見る。タイムラプスは1秒内にも多くの作業が含まれるので、必要箇所では1秒未満のフレーム列へ戻る。全編を一律に大量抽出することを目的にしない。

濡れや照明による見えの変化だけで、別材種の追加と判断しない。例えば白いシートの暗色化では、搬入前後・保持する手・接触周辺を追い、同じ材料の変化か新しい材料かを区別する。必要な抽出間隔は動作に合わせ、固定の秒数をすべての動画へ適用しない。

撮影開始の状態を、その工程の最初や未処理状態と決め付けない。元動画のPTSと日誌の時計時刻の対応が未確認なら、別々の情報として示し、「映像冒頭の状態」等の観察できる範囲へ限定する。

画面左・右の別部品を追い、持ち替えや裏返し後に同一性が分からなくなった時点を残す。動作の種類が分かったことと、その部品の全表裏処理順が分かったことを区別する。見えない接触順は、説明用の補間とするか短い編集上の省略へ置き換える。

字幕の「積層」「含浸」「位置決め」を、それだけで絵コンテにしない。材料の形、工具の縁、保持点、局所的な変形、状態の変化まで確認する。接触主体が見えない場合も、何がどこへ作用したかを説明できるか検討する。

確認した主要動作を場面へ対応付け、抜けた動作には省略理由を残す。材料の供給、塗り広げ、持ち替え、膜の除去など、同じ工程名の中でも前後の状態を変える動作を一つに潰さない。すべての細かな反復を再現する必要はない。

分割数が分かっても、境界の方向・位置が分かるとは限らない。未確認の継ぎ目や切り込みを実物モデルへ追加しない。工具の種類を同定できない場合も、架空の工具や握り方で埋めず、確認できる接触点・材料の分離・結果で示す。描画上の補間という注記だけで、製法に関わる未知の構造や手順を確定しない。

## 台帳

少なくとも次の内容をつなぐ。MDとJSONを両方同じ量で作る必要はない。

| 単位    | 欄                                                                                                                     |
| ------- | ---------------------------------------------------------------------------------------------------------------------- |
| 根拠E等 | 資料ID、種類、対象代・部品・作業日、URLまたはファイル、画像／実PTS、確認内容、未確認、確認者・確認日が分かればその情報 |
| 部品M等 | ID、名称、形の特徴、表裏・方向、相対比率と根拠、硬さ／柔軟性、他部品との関係、モデルに補間した箇所                     |
| 操作A等 | ID、対象部品ID、前状態、接触主体と位置、方向・変形、処理する範囲、後状態、注意点、根拠、補間                           |
| 場面S等 | ID、使うモデル・操作、見せる視点、字幕、始終状態、出典、視聴後に分かること                                             |

根拠の種類は、観察O、記録者の説明R、年代付きWiki W、ユーザー／有識者の追加説明U、描画の補間Eなど、混同しない表記ならよい。Uの発言者が有識者と確認できていなければ、勝手に有識者承認へ分類しない。

## 後から補足が来た場合

新しい補足を独立した根拠として保存し、何を置き換えるかを示す。例えば「接着剤も全体に塗る」という補足を含浸場面へ適用するなら、対象を「そのCF面の処理範囲」と明示する。すべての部材・袋・両面・別工程へ適用しない。対象が判別できず描画が変わる場合だけ短く確認する。

歴史的な事実の訂正と、次年度に試したい改善案を分ける。別の日の対策案を今回実施したと描かない。原因不明の失敗に、もっともらしい因果関係を追加しない。

画像やモデルが確認できないからといって、既存の知識項目を消したり書き換えたりしない。動画の出力とWikiへの公開・反映は別の範囲として扱う。
